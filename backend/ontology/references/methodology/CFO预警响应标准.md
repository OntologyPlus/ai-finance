# 方法论：CFO预警响应标准

---

## 1. 核心原则

**预警是实时信号系统，不是事后惩罚机制。**

预警的本质是"苗头阶段就纠偏"——偏差刚冒头时低成本止损，而非秋后算账。

两个时间窗口：
- **苗头期**：损失规模小、纠偏成本低 → 预警的价值窗口
- **复盘期**：损失已发生，只能事后补救 → 预警失效后的补救

---

## 2. 预警分级标准

| 灯色 | 级别 | 偏差条件 | 超期条件 | 响应时效 |
|------|------|---------|---------|---------|
| 🔴 红 | 红色 | 超10%偏差 | 已超截止日期 | ≤3工作日 |
| 🟠 橙 | 橙色 | 5–10%偏差 | 距截止日期≤3天 | ≤5工作日 |
| 🟡 黄 | 黄色 | 3–5%偏差 | 距截止日期≤7天 | ≤7工作日 |
| 🔵 蓝 | 蓝色 | <3%偏差 | 距截止日期>7天 | 记录存档 |

---

## 3. 预警响应闭环流程

### 3.1 业务响应 + 财经BP确认（双签闭环）

```
预警触发
  → 责任人接收预警，确认业务响应措施
  → 财经BP验证响应措施有效性（横向对标视角）
  → 双方在系统双签确认闭环
  → 预警关闭，归档记录
```

**闭环判定标准**：
1. 业务响应：责任人已在系统中确认处理措施
2. 财经BP确认：财务BP验证闭环措施有效性
3. 双签归档：系统记录归档

### 3.2 响应时效规则

| 预警级别 | 响应时限 | 超时处理 |
|---------|---------|---------|
| 红色 | ≤3工作日 | 系统升级至管委会，冻结相关预算 |
| 橙色 | ≤5工作日 | 财经BP电话跟进，冻结超期部分预算 |
| 黄色 | ≤7工作日 | 记录在案，下期经营分析会专项汇报 |

---

## 4. 象限预警规则

| 象限 | 预警触发条件 | 响应优先级 |
|------|------------|----------|
| **发展** | 执行率 < 70% 或 超期 | P0（最高） |
| **收缩** | 执行率 > 60% | P1（关注是否应压降但未压降） |
| **稳定** | 执行率 < 50% 或 > 75% | P2 |
| **探索** | 执行率 > 80%（异常高） | P1（高不确定性领域高执行率需审查） |

---

## 5. 预警升级规则

当出现以下情况时，预警自动升级至管委会：

| 触发条件 | 升级动作 |
|---------|---------|
| 红色预警超期≥5工作日未闭环 | 升级至管委会专题汇报 |
| 超期预警 > 3条 | 触发紧急告警 |
| 象限组合严重失衡 | 触发战略资源重配讨论 |
| B→A转换连续2季度未达标 | 冻结剩余额度，上报管委会 |

---

## 6. 预警与 PDCA 联动

预警闭环档案是 PDCA 复盘的核心输入：

```
预警触发 → 响应闭环 → 归档记录
                        ↓
               季度PDCA复盘提取预警数据
                        ↓
               分析预警根因 → 纳入改进行动
                        ↓
               次年预算配置调整输入
```

---

## 7. 预警数据质量规则

| 规则 | 说明 |
|------|------|
| 预警ID唯一性 | 每个预警有唯一ID，可追溯历史记录 |
| 响应时间记录 | 系统自动记录响应时间，支持时效统计 |
| 数据真实性 | 预警数据必须真实，禁止虚构预警完成闭环 |
| 阈值动态调整 | 每季度审视阈值合理性，按业务阶段调整 |

---

## 8. 违规处理

| 违规场景 | 处理方式 |
|---------|---------|
| 虚假闭环（未实际响应即标注已闭环） | 退回闭环申请，情节严重者上报管委会 |
| 超期预警不响应 | 系统自动升级，冻结相关预算额度 |
| 预警数据造假 | 系统标记，审计介入 |
| 未按要求在经营分析会汇报预警情况 | 纳入绩效考核，财经中心记录 |
