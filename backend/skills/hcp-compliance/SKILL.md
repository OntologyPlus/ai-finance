# HCP费用合规审查

## 何时使用此技能
在HCP互动或付款操作时触发合规检查、需要进行HCP合规风险评估，或用户询问"HCP合规"、"互动审查"、"付款限额"、"合规风险"时使用。

## 工作流程

本技能采用**网关模式**：HCP验证是付款的前提，互动合规检查和付款限额检查是并行网关，综合风险评估是汇总节点。

### 步骤1：HCP身份验证（HR-026）
- **为什么**：未验证的HCP可能存在身份造假风险，付款前必须验证。
- 验证基本信息完整性（姓名、机构、科室、专业领域）
- 验证机构合规性
- 验证专业领域匹配
- 验证通过后状态更新为"已验证"

### 步骤2：互动合规检查（HR-028）
- **为什么**：不完整的互动记录无法证明互动的真实性和合规性。
- 检查互动记录完整性：类型、日期、目的、内容摘要、参与人员
- 检查月度互动频次（HR-029）
- 标记合规/不合规状态

### 步骤3：付款限额检查（HR-027）
- **为什么**：超过年度限额的付款可能暗示不当利益输送。
- 前置条件：HCP必须已验证（HR-026）
- 检查付款后年度总额是否超过限额
- 超限额须合规总监特别审批

### 步骤4：综合风险评估
- **为什么**：单一维度检查可能遗漏系统性风险。
- 频次风险：年度互动次数评估
- 金额风险：年度付款占限额比例
- HR-029违规：月度互动超过3次的月份
- 综合风险评分（0-100）

## 输出格式
```
HCP合规风险报告 [期间]
- HCP：[姓名]（[编号]）
- 验证状态：[已验证/待验证/验证失败]
- 年度互动：[N]次（合规[N]/不合规[N]）
- 年度付款：[N]元（限额[N]元，占比[N]%）
- 风险等级：[低/中/高/极高]
- HR-029违规月份：[N]个
- 建议：[具体建议]
```

## 边界情况
- 未验证的HCP不能进行付款操作
- 互动记录不完整时标记为不合规
- 月度互动超过3次自动触发审查
- 付款接近限额时预警（80%以上）

## 方法论参考

| 方法论 | 引用原因 |
|--------|---------|
| CFO预警响应标准 | HCP合规风险需按预警分级标准进行风险评估和升级，超限额和频次违规需按响应时效及时处理 |
| CFO交互标准与沟通范式 | 合规审查结果需按合规审查场景沟通范式呈现，风险升级时按异常升级沟通范式即时上报 |
